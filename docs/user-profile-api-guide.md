# User Profile API Guide

This guide covers the user profile endpoints: updating the full name, uploading/replacing the profile photo, deleting the profile photo, and how the profile photo is returned by the auth info endpoint.

All request/response examples below were captured from a successful test run against the local dev server.

---

## Endpoint Summary

| Method | Endpoint | Description | Auth | Body / Form |
|---|---|---|---|---|
| `PATCH` | `/api/users/me` | Update the logged-in user's full name | Bearer token | `application/json`: `name` |
| `POST` | `/api/users/me/photo` | Upload or replace the profile photo (JPEG, PNG, WebP max 2 MB) | Bearer token | `multipart/form-data`: `file` |
| `DELETE` | `/api/users/me/photo` | Delete the profile photo | Bearer token | — |
| `GET` | `/api/auth/info` | Get logged-in user info, including `photoProfile` (pre-signed URL) when set | Bearer token | — |

**Storage notes**

- The database stores only the R2 `objectKey` (`Users.profile_picture`). It is never returned to clients.
- The API always returns a fresh pre-signed URL (`photoProfile`). Signed URLs expire after **3600 seconds (1 hour)**.
- On replace, the old object is deleted from R2 only after the new object is saved and the database is updated.
- If uploading succeeds but the database update fails, the just-uploaded object is deleted so it does not linger as an orphan.

## 1. Update Full Name (`PATCH /api/users/me`)

**Headers**
- `Authorization: Bearer <access_token>`
- `Content-Type: application/json`

**Request Body**
```json
{
  "name": "Valid New Name"
}
```

**Response (HTTP 200 OK)**
```json
{
  "status": "success",
  "message": "profile updated successfully",
  "data": {
    "id": "228dc2c0-d3cb-4cae-8c45-d85fc2ef406f",
    "username": "pt_gd6yx8",
    "name": "Valid New Name",
    "email": "profiletest_gd6yx8@example.com",
    "createdAt": "2026-10-16T15:54:41.392Z"
  }
}
```

**Validation (HTTP 400 Bad Request)** — name is trimmed; empty/whitespace-only or shorter than 3 chars is rejected:
```json
{
  "status": "fail",
  "message": "Validation Error",
  "errors": [
    {
      "path": "body.name",
      "message": "Name must be at least 3 chars"
    }
  ]
}
```

## 2. Upload / Replace Profile Photo (`POST /api/users/me/photo`)

**Headers**
- `Authorization: Bearer <access_token>`
- `Content-Type: multipart/form-data`

**Form Data**
- `file`: `<image>` (binary; JPEG, PNG, or WebP; max 2 MB)

**Response (HTTP 201 Created)**
```json
{
  "status": "success",
  "message": "profile photo uploaded successfully",
  "data": {
    "userId": "228dc2c0-d3cb-4cae-8c45-d85fc2ef406f",
    "photoProfile": "https://task-management-files.example.com/uploads/profile-pictures/228dc2c0-d3cb-4cae-8c45-d85fc2ef406f_1792166090307_6631b637-9739-4d91-89af-8fdabd9b5925.png?X-Amz-Algorithm=AWS4-HMAC-SHA256&X-Amz-Credential=...&X-Amz-Date=20261016T155451Z&X-Amz-Expires=3600&X-Amz-Signature=...&X-Amz-SignedHeaders=host"
  }
}
```

> The object key is generated by the server (`uploads/profile-pictures/<userId>_<timestamp>_<uuid>.<ext>`). The user's original file name is not used.

Calling this endpoint again replaces the photo: the new file is stored, the DB is updated, and the previous object is deleted from R2.

---

## 3. Delete Profile Photo (`DELETE /api/users/me/photo`)

**Headers**
- `Authorization: Bearer <access_token>`

**Response (HTTP 200 OK)**
```json
{
  "status": "success",
  "message": "profile photo deleted successfully",
  "data": {
    "userId": "228dc2c0-d3cb-4cae-8c45-d85fc2ef406f",
    "photoProfile": null
  }
}
```

**No photo set (HTTP 404 Not Found)**
```json
{
  "status": "fail",
  "message": "Profile photo not found"
}
```

## 4. Get Logged-in User Info (`GET /api/auth/info`)

**Headers**
- `Authorization: Bearer <access_token>`

**Response with a photo set (HTTP 200 OK)**
```json
{
  "status": "success",
  "data": {
    "id": "228dc2c0-d3cb-4cae-8c45-d85fc2ef406f",
    "username": "pt_gd6yx8",
    "name": "Valid New Name",
    "email": "profiletest_gd6yx8@example.com",
    "createdAt": "2026-10-16T15:54:41.392Z",
    "photoProfile": "https://task-management-files.example.com/uploads/profile-pictures/228dc2c0-d3cb-4cae-8c45-d85fc2ef406f_1792166090307_6631b637-9739-4d91-89af-8fdabd9b5925.png?X-Amz-Algorithm=AWS4-HMAC-SHA256&X-Amz-Expires=3600&X-Amz-Signature=..."
  }
}
```

**Response without a photo (HTTP 200 OK)** — `photoProfile` is `null`:
```json
{
  "status": "success",
  "data": {
    "id": "228dc2c0-d3cb-4cae-8c45-d85fc2ef406f",
    "username": "pt_gd6yx8",
    "name": "Valid New Name",
    "email": "profiletest_gd6yx8@example.com",
    "createdAt": "2026-10-16T15:54:41.392Z",
    "photoProfile": null
  }
}
```

> The raw `profilePicture` object key is intentionally not exposed; only the generated `photoProfile` URL is returned.

## Error / Validation Reference (verified)

| Scenario | Endpoint | Status | Body |
|---|---|---|---|
| Invalid file type (e.g. `.txt`) | `POST /api/users/me/photo` | `400` | `{"status":"fail","message":"Invalid file type. Allowed types: image/jpeg, image/png, image/webp"}` |
| File too large (> 2 MB) | `POST /api/users/me/photo` | `413` | `{"status":"fail","message":"File too large. Maximum allowed size exceeded."}` |
| No / invalid token | any | `401` | `{"status":"fail","message":"Unauthorized: No token provided"}` |
| Name too short / whitespace-only | `PATCH /api/users/me` | `400` | `{"status":"fail","message":"Validation Error","errors":[{"path":"body.name","message":"Name must be at least 3 chars"}]}` |
| Delete when no photo exists | `DELETE /api/users/me/photo` | `404` | `{"status":"fail","message":"Profile photo not found"}` |

## Notes for Frontend

- Display `photoProfile` directly as an `<img src>`; refresh by re-calling `GET /api/auth/info` after it expires (1 hour).
- For uploads, send `multipart/form-data` with the field name `file`.
- After a successful upload, use the returned `photoProfile` immediately; it is a fresh signed URL.
